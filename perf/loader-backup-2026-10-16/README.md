# WCH backup/recovery evidence

[Findings and limits](../../docs/WCH_BACKUP_RECOVERY.md).
No loader entry or device command occurred.

`verify_model.py` is an original standard-library semantic model with nine
generated controls. It accepts no device or firmware-file inputs, has no USB,
network, command encoder, loader entry, erase or write implementation, and never
saves memory contents. Run from the repository root:

```bash
python perf/loader-backup-2026-10-16/verify_model.py
```

This reproduces `synthetic-results.json`. It does not execute vendor instructions,
validate malformed packets or establish a real dongle's behaviour. The older
model reconstructs generated bytes using an explicitly supplied known boundary
and session mask. Newer checks reject that walk and latch a mismatch. The
inspected start guard allows bounded range crossing; no arbitrary-read or
complete-backup claim follows. Model input bounds are narrower than wire input.

- `assembly-analysis.json`: static section/latch references in the hash-pinned
  generic 2.31/2.40 assembly, not Nanoleaf code. No rebuild claim.
- `research-sources.json`: primary URLs, chronology, source hashes and coverage
  limits. 2.50 was read in the browser; no raw-file hash is claimed for it.
- `vendor-methods.json`: pinned desktop method offsets and semantic findings.
- `protocol-history-summary.json`: all ten returned revisions and body hashes.

Third-party assembly, executables, firmware images, keys, factory data,
controller identifiers, calibration and USB traces are not included. CI/local
release contracts exercise only generated controls. These scripts are operator
analysis tools, not application dependencies.
